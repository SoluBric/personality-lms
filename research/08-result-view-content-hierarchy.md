# Result View Content Hierarchy

This document outlines what should appear where in the app. It is a flexible UX/content plan, not a locked wireframe.

## Individual Result View

### 1. Result Header

Purpose: immediate recognition.

Content:

- User name and role.
- Main type number and Aephoria-style heading.
- Traditional label as secondary text.
- Trifix code.
- Instinct stack chip, if available.

Example:

- "Maya Naidoo"
- "3 · Ambitious Task Master"
- "Traditional reference: Achiever / Performer"
- "Trifix 3-8-5 · so/sp/sx"

### 2. Interactive Result Ring

Purpose: visual assessment overview.

Content:

- Nine segments around the ring.
- Segment length or intensity based on score.
- Main type emphasized.
- Second and third trifix points connected or highlighted.
- Hover/click reveals score, type heading, center, and quick interpretation.

Default interaction:

- Main type selected on load.
- Clicking a type opens the type detail panel.
- A toggle switches between "All types", "Trifix", and "Centers".

### 3. Main Pattern Summary

Purpose: explain the primary result in plain language.

Content:

- Healthy expression.
- Overused expression.
- Current development question.
- Main recommended course.

Example structure:

- "At its best..."
- "Under pressure..."
- "Development question..."
- "Recommended next course..."

### 4. Trifix Story

Purpose: explain how the top three interact.

Content:

- One short paragraph.
- Three small cards for first, second, third type.
- One "likely strength" and one "likely friction".

Example:

- `3-8-5`: "Outcome focus leads, supported by decisive protection and analytical control."
- Strength: fast strategic execution.
- Friction: intensity plus analysis may reduce emotional buy-in.

### 5. Instinct Context

Purpose: add nuance without taking over the page.

Content:

- Compact stack label.
- One practical paragraph.
- Optional "examples in your courses will lean toward..." note.

Example:

- `sp/so/sx`: "Practical security first. Learning examples should emphasize routines, resources, energy, and sustainable delivery."

### 6. Strengths and Risks

Purpose: make the result useful.

Content:

- Three strength bullets.
- Three risk bullets.
- One "watch for this in teams" note.

### 7. Recommended Pathway

Purpose: bridge assessment to LMS.

Content:

- Three primary course cards:
  - Main type maturity.
  - Trifix calibration.
  - Underused capacity or team gap.
- Each card includes why recommended, duration, format, and first action.

### 8. All Nine Capacities

Purpose: avoid type-locking.

Content:

- Compact grid of all nine type capacities.
- Current score indicator.
- "Build this capacity" action.

### 9. Reflection and Progress

Purpose: create LMS continuity.

Content:

- One reflection prompt.
- Active course progress.
- Completed practices.
- Saved notes.

## Team Result View

### 1. Team Header

Content:

- Team name.
- Members.
- Dominant team capacities.
- Lowest team capacities.

### 2. Team Ring / Distribution

Content:

- Aggregate type scores.
- Center balance.
- Member overlay toggle.

### 3. Team Strengths

Content:

- Two or three likely strengths.
- Link each strength to the types creating it.

### 4. Team Risks

Content:

- Two or three likely risks.
- Phrase risks as coordination patterns, not character flaws.

### 5. Team Dynamics Notes

Content:

- Pairing insights.
- Overrepresented patterns.
- Missing-capacity prompts.

### 6. Team Learning Pathway

Content:

- One team workshop.
- One individual follow-up course for each member.
- One suggested team ritual.

## Navigation Implications

- The dashboard should let the user move between "My Result", "My Courses", "My Team", and "All Capacities".
- The result page should not be a dead end. Every insight should have a next action.
- The course page should always preserve the "why this was recommended" link back to the result.
